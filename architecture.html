Tribe · teammate guide

One visible agent loop.

Tribe is a small Python CLI that connects a model to workspace tools, with sessions and approvals around the loop.

Main modules

CLI & wiring

Parses run/chat/resume, resolves settings, and assembles the runtime.

src/tribe/cli.py

Terminal UI

Textual chat, transcript, commands, login, and interactive approvals.

src/tribe/tui/app.py

Agent loop

Records turns, asks the model, runs requested tools, and stops on limits or a final answer.

src/tribe/agent/loop.py

Sessions & messages

Typed message events stored as append-only JSONL for each session.

store.py · messages.py

Context

Selects usable history and compacts older turns when the context budget fills.

builder.py · compaction.py

Models

Provider registry and adapters keep the loop independent of Anthropic or OpenAI-compatible APIs.

registry.py · base.py

Tools & workspace

Validates tool inputs and provides read, grep, write, and bash capabilities scoped to a workspace.

Approval policy

Observability & limits

Observers report activity; run limits bound rounds, tool time, failures, and cancellation.

How the pieces connect

CLI ── builds ──► AgentLoop ◄── Observer (console / TUI)
                     │
          ┌──────────┼───────────┐
          ▼          ▼           ▼
     SessionStore  ContextBuilder  Model adapter
          ▲                       │
          │                  response / tool calls
          │                       ▼
          └──── tool result ◄─ ApprovalGate ─► Workspace tools
                                      │             (read/grep/write/bash)
                                      └── allow / ask / deny

The session is the durable record; context is a bounded view of that record sent to the model.

A request, end to end

  1. Entry: CLI resolves provider, model, workspace, and approvals; creates or resumes a session.
  2. Record: AgentLoop appends the user message through SessionStore.
  3. Prepare: ContextBuilder selects history; compaction summarizes older turns if needed.
  4. Ask: The provider adapter sends system instructions, history, and tool specs to the model.
  5. Act or answer: A final response is saved and displayed. For tool calls, the gate checks policy, then a validated tool runs within the workspace.
  6. Repeat: Tool results are appended to the session and fed into the next model round until a final answer, cancellation, or run limit.
